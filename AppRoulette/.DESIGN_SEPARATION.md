# View と ViewModel の責務分離 - 改善計画実装ドキュメント

## 概要

AppRoulette の優先度 C 改善「継続開発しやすくする設計改善」として、**View と ViewModel の責務分離**を実装しました。特に、アニメーション状態管理とルーレット回転角度計算を ViewModel に移行し、MainWindow.xaml.cs（View）の責務を描画・イベント処理に限定しました。

## 改善前の問題

### MainWindow.xaml.cs に集約されていた責務
1. **アニメーション状態管理**
   - `_rotationAngle`, `_spinStartAngle`, `_spinTotalRadians`, `_spinElapsedSec` などの状態フィールド
   - `MIN_SPIN_RADIANS`, `MAX_SPIN_RADIANS`, `SPIN_DURATION_SEC` などの定数

2. **角度計算ロジック**
   - `CalcTargetAngle(int selectedIndex, IReadOnlyList<RouletteItem>? items)` メソッド
   - Weight に基づくルーレット目標角度の算出

3. **アニメーション計算**
   - `EaseOutCubic(float t)` easing 関数
   - タイマーでの角度進行計算

4. **UI 同期**
   - `PropertyChanged` ハンドラーでの TextBox/ComboBox 手動同期
   - タイマーティック時の再描画トリガー

### 結果
- View と ViewModel の境界が曖昧
- ビジネスロジック（角度計算）が View に混在
- テスト性が低い（UI 層に依存する計算）
- 再利用性が低い（計算ロジックが View 内に隔離）

## 改善後の設計

### 新規ViewModel: SpinAnimationViewModel

```csharp
public class SpinAnimationViewModel : ObservableObject
{
	// 定数の集約
	public const float MIN_SPIN_RADIANS = MathF.PI * 8f;
	public const float MAX_SPIN_RADIANS = MathF.PI * 14f;
	public const float SPIN_DURATION_SEC = 3.5f;

	// 状態の集約
	public float RotationAngle { get; set; }
	public float SpinStartAngle { get; set; }
	public float SpinTotalRadians { get; set; }
	public float SpinElapsedSec { get; set; }

	// 計算メソッド
	public float AdvanceAnimation(int deltaMs)
	public float GetCurrentRotationWithEasing()
	public static float EaseOutCubic(float t)
	public void ResetAnimation()
}
```

**役割**: ルーレット回転アニメーションの状態と計算を単一の責務に集約

### MainViewModel への変更

1. **SpinAnimation プロパティの追加**
   ```csharp
   public SpinAnimationViewModel SpinAnimation
   {
	   get => _spinAnimationViewModel;
   }
   ```

2. **CalcTargetAngle の移動（静的メソッド）**
   ```csharp
   public static float CalcTargetAngle(
	   int selectedIndex,
	   IReadOnlyList<RouletteItem>? items)
   ```
   - 重み付きルーレットの目標角度を計算
   - View から呼び出し可能なビジネスロジック

### MainWindow.xaml.cs への変更

#### 削除した要素
- アニメーション状態フィールド 4 個
- アニメーション定数 3 個
- `EaseOutCubic(float t)` メソッド
- `CalcTargetAngle()` メソッド
- `PropertyChanged` ハンドラーの UI 同期ロジック（大幅削減）
- 不完全な `GetAverageWeight()` メソッド

#### 修正した要素

1. **RouletteCanvas.Draw**
   ```csharp
   // Before
   RouletteRenderer.Draw(..., _rotationAngle);

   // After
   RouletteRenderer.Draw(..., ViewModel.SpinAnimation.RotationAngle);
   ```

2. **StartSpinAnimation()**
   ```csharp
   // Before
   _spinStartAngle = _rotationAngle;
   _spinElapsedSec = 0f;
   var targetAngle = CalcTargetAngle(...);
   _spinTotalRadians = ...;

   // After
   var spinAnimation = ViewModel.SpinAnimation;
   spinAnimation.SpinStartAngle = spinAnimation.RotationAngle;
   spinAnimation.SpinElapsedSec = 0f;
   var targetAngle = MainViewModel.CalcTargetAngle(...);
   spinAnimation.SpinTotalRadians = ...;
   ```

3. **OnSpinTimerTick()**
   ```csharp
   // Before
   _spinElapsedSec += TIMER_INTERVAL_MS / 1000f;
   var t = Math.Min(_spinElapsedSec / SPIN_DURATION_SEC, 1f);
   var eased = EaseOutCubic((float)t);
   _rotationAngle = _spinStartAngle + _spinTotalRadians * eased;

   // After
   var spinAnimation = ViewModel.SpinAnimation;
   spinAnimation.AdvanceAnimation(TIMER_INTERVAL_MS);
   if (spinAnimation.IsAnimationComplete) { ... }
   ```

4. **PropertyChanged ハンドラー（簡素化）**
   - TextBox/ComboBox の手動同期を削除
   - Binding による自動同期に依存
   - アイテム数/グループ変更時のみ再描画トリガー

## 責務分離のメリット

### 1. 保守性の向上
- ViewModel が単一責任を持つ
- アニメーション計算ロジックが独立
- 将来の変更時に影響範囲が明確

### 2. テスト性の向上
- `SpinAnimationViewModel` を単体テスト可能
- `MainViewModel.CalcTargetAngle()` を独立してテスト
- Mock/Stub の適用が容易

### 3. 再利用性の向上
- アニメーション計算を他の画面/機能で再利用可能
- ビジネスロジック（角度計算）を View 以外で活用可能

### 4. 開発効率の向上
- View と ViewModel の境界が明確
- 新機能追加時のリスク低減
- デバッグが容易（責務が明確に分離）

## まとめ

View と ViewModel の責務を明確に分離することで、AppRoulette のコードベースは以下のように改善されました:

- **保守性**: ✅ アニメーション計算が ViewModel に集約
- **テスト性**: ✅ ビジネスロジックが UI 依存から解放
- **再利用性**: ✅ 計算ロジックが独立して活用可能
- **拡張性**: ✅ 新機能追加時の影響範囲が限定

この設計改善により、「継続開発しやすくする」という目標が達成されています。
